# Positioning Notes

## Core thesis

Eduardo turns ambiguous ideas into functional systems.

The site should not feel like a sales page for websites. It should feel like
proof that Eduardo can enter an unclear domain, understand the human intent,
model the hidden constraints, and build software that makes the next step real.

## Best short version

I turn ambiguous ideas into functional systems.

## Longer version

Some projects start as a dream, a messy workflow, or a technical question
nobody has shaped yet. My job is to translate the human intent into
constraints, logic, interfaces, and software that can survive contact with
reality.

## Edge

The edge is not raw coding speed. The edge is knowing what the system should be.

Many developers can implement a clearly defined feature. The harder and more
interesting work is figuring out what the real problem is, what constraints
matter, what should be automated, what should stay human, and what a first
working version should prove.

## Useful metaphors

- Human intent into machine logic.
- Ambassador between people and systems.
- Reality check for ambitious ideas.
- Path from dream to working machinery.
- Engineer/scientist: observe, model, test, build.

## Tone

Calm, specific, proof-driven. Avoid "hire me to build your website" language.
Prefer artifacts, case files, interactive demos, and short explanations of the
thinking behind the work.
