# Positioning Notes

## Core thesis

Eduardo turns unclear software ideas into working proof.

The site should not feel like a sales page for websites. It should feel like
evidence that Eduardo can enter an unclear domain, understand the human intent,
model the hidden constraints, and build the smallest useful system that makes
the next decision obvious.

## Best short version

I turn unclear software ideas into working proof.

## Longer version

My best work starts in the unclear middle: when the goal is real, the domain is
messy, and the next technical move is not obvious. My job is to learn the
domain, find the constraint that matters, and build enough of the system to
make the next decision obvious.

## Edge

The edge is not raw coding speed. The edge is problem formation.

Many developers can implement a clearly defined feature. The harder and more
interesting work is sitting in the uncertainty before the ticket exists:
figuring out what the real problem is, what constraints matter, what should be
automated, what should stay human, and what a first working version should
prove.

## Useful metaphors

- Bring me the thing before it is a clean ticket.
- Messy input, clear model, working proof.
- Explore broadly, build narrowly.
- Smallest system that can teach something true.
- Context into constraints.

## Tone

Calm, specific, proof-driven. Avoid "hire me to build your website" language
and abstract self-mythology. Prefer case files, concrete constraints, visible
artifacts, and short explanations of what each project proved.

Interactive demos are only worth adding when they are tied to a real project
and reveal how the work was modeled. Random demos, even clever ones, make the
site feel like it is trying too hard.
